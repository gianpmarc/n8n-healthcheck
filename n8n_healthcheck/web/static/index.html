Step 1 of 6 What this tool does

n8n-healthcheck inspects a self-hosted n8n instance and makes one file about it, the environment profile, for the person who asked you for it. This is what it does, before you give it anything.

  • It only reads. Nothing is changed on your instance, your database or your cluster.
  • It runs here and contacts only what you point it at. The check runs on the machine where n8n-healthcheck was started. It contacts the n8n URL, the database, Redis, and the cluster of the kubectl context you choose. A redirect the n8n URL answers with is followed, and those requests use the proxy settings of this machine if it has any; the API key, when you give one, goes to that URL only, never to another host or through a proxy. What the tool does not control: psql and kubectl connect and sign in as their own configuration says (a credential helper may contact your provider's sign-in service), and names are looked up by this machine's resolver. The report and the file are sent nowhere.
  • You end with one file, which you review and send yourself. You can leave out any entry of it except the n8n version, which is always part of the file.

What the file never contains

No secret, host name, URL, IP address, file path, e-mail address, or Deployment, namespace or registry name. A setting's value is written only when it is a boolean, a number or a fixed word; otherwise the file only says it is set.

One exception. The optional one-line reference you can type in step 5, for example a ticket number, is written to the file as you type it.

What the tool reads, computes and writes is set out in What n8n-healthcheck does, with the tests that hold each statement. The link opens the tool's public repository on github.com in a new tab; this page itself loads nothing from outside.

Step 2 of 6 Debug information Required

n8n writes a short text about itself. The file is built on it: it states the n8n version, which every later conversation needs. Without it no file can be made.

  1. In n8n, open Help, then About n8n.
  2. Choose Debug information, then Copy.
  3. Paste the text below and press Check the text.

Read from the text. Nothing was collected from the instance yet.

The instance ids, the host ids and the browser's user agent in the text are not taken from it: nothing of them is kept, shown or written anywhere.

Create a key in n8n under Settings > n8n API, for this run only, and delete it there afterwards. It is used for GET requests to this URL and is neither kept nor shown again. Where n8n lets you choose scopes, these are enough: insights:read, execution:list, workflow:list, user:list, user:read. Use the key of the owner or of an admin: any other key sees only its own user's workflows and executions, and the numbers are then marked as partial.
